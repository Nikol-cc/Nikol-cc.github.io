# Linux 内核源码阅读

阅读 Linux 内核源码时，建议从“系统行为”反查代码，而不是从目录开始漫无目的地阅读。一个串口、网卡或自定义字符设备，都可以沿着用户接口、系统调用、内核子系统、驱动回调和硬件寄存器逐层展开。

## `start_kernel()` 之后发生什么

`start_kernel()` 是通用内核初始化的主要入口，典型顺序包括：

1. 建立基础内存管理和 slab 分配器。
2. 初始化中断、定时器、调度器和 RCU。
3. 初始化 VFS、驱动模型、网络和文件系统子系统。
4. 通过 `rest_init()` 创建内核线程。
5. 启动用户空间的 `init` 程序。

具体顺序会随内核版本和配置变化，因此源码阅读必须同时对照 `.config`、架构代码和启动日志。

## 从日志反查源码

```sh
dmesg -w
dmesg | grep -Ei 'probe|firmware|dma|timeout|irq'
cat /proc/interrupts
cat /proc/iomem
cat /proc/modules
```

看到一条 `probe success` 日志时，应继续查找打印它的函数、该函数由哪个总线调用，以及前面是否完成了时钟、复位、regulator、GPIO 和 DMA 资源申请。

## 阅读并发代码

- 自旋锁适合短临界区和中断上下文，不能在持锁时睡眠。
- 互斥锁适合进程上下文，可以睡眠等待资源。
- `spin_lock_irqsave()` 不只是加锁，还会保存并关闭本地中断，释放时必须配对恢复。
- `READ_ONCE()`、`WRITE_ONCE()` 用来明确告诉编译器某个共享变量可能被并发访问。
- DMA 场景还要结合 `dma_map_single()`、缓存一致性和内存屏障一起分析。

源码阅读的最终结果应该是一张“调用路径 + 状态变化 + 资源生命周期”图，而不是一组孤立的函数笔记。
