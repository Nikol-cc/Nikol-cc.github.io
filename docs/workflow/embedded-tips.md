# 嵌入式开发技巧

## 从现象建立证据链

把“不能启动”“偶发丢包”“驱动不工作”拆成可观测的事实：

1. 固定硬件版本、供电、时钟、软件提交和输入数据。
2. 记录首次出现问题的时间点和最后一条正常日志。
3. 把软件日志、寄存器快照、示波器/逻辑分析仪波形和复现条件放在同一份记录中。
4. 每轮只改变一个变量，并保留前后结果。

## 日志与断言

日志应包含模块、事件、关键参数和错误码，避免只打印“failed”。在资源有限的 MCU 上，可以用级别宏和静态格式字符串控制体积。

```c
#define ASSERT_OR_RETURN(condition, error) \
    do { \
        if (!(condition)) { \
            LOG_ERROR("%s:%d: %s", __FILE__, __LINE__, #condition); \
            return (error); \
        } \
    } while (0)
```

断言适合发现编程错误；外部输入、通信错误和资源不足应走可恢复的错误处理路径。

## 时间、空间与吞吐量

不要凭感觉判断性能。测量：

- 中断进入到退出的时间；
- DMA 一次传输的字节数和剩余计数；
- 队列峰值长度和丢包次数；
- 栈高水位、堆剩余量和内存碎片；
- Linux 用户态、内核态 CPU 时间和 I/O 等待。

计算吞吐量时统一单位，并区分理论带宽、总线有效带宽和应用层有效载荷。DMA 加速并不代表系统更快，缓存维护、拷贝和同步也要计入成本。

## 缓冲区所有权

任何异步数据通路都应画出所有权状态：空闲、DMA 使用、ISR 已完成、任务处理中、应用已消费。状态切换必须有唯一的生产者和消费者；不要让多个上下文通过“约定”同时修改长度和索引。

## 版本与回滚

每个可烧录产物都应记录 Git 提交、编译器、链接脚本、设备树、配置文件、校验和和生成时间。升级 OpenSSH、防火墙、启动脚本或根文件系统时，保留串口、备份和回滚介质；先验证配置，再启用开机服务。

## 最小化复现

将复杂工程缩成一个最小程序、最小设备树节点或最小数据包。先证明“硬件能响应”，再叠加 DMA、缓存、任务和协议层。对于 Linux 驱动，先验证 `probe`、资源映射、中断和 `/dev` 节点，再验证完整业务路径。
