# GD32H759 芯片资源

GD32H759 是面向高性能控制和工业通信的 Cortex-M7 MCU，最高 600 MHz，集成最高 4 MB Flash 和 1 MB SRAM，支持 CAN-FD，并提供 LQFP176、BGA176 等封装选项。高性能的重点不只是主频，还包括缓存、MPU、总线矩阵、DMA 和存储器区域之间的协作。

## 资源概览

| 资源   | 关注点                                                             |
| ------ | ------------------------------------------------------------------ |
| CPU    | Cortex-M7，最高 600 MHz，适合控制、DSP 和图形/数据处理             |
| 存储器 | 最高 4 MB Flash、1 MB SRAM，按具体料号和封装变化                   |
| 缓存   | I-Cache / D-Cache 会影响 DMA 缓冲区的一致性                        |
| MPU    | 用于设置可执行、可缓存、只读和设备内存属性                         |
| 通信   | CAN-FD、Ethernet、USB、USART/UART、SPI、I2C 等，具体实例按料号确认 |
| DMA    | 高速外设数据搬运，重点是总线权限、缓存维护和缓冲区布局             |
| 封装   | GD32H759 常见 LQFP176、BGA176 选项                                 |

## Cache 与 DMA

CPU 写入 D-Cache 后，外设可能仍从 RAM 读取旧数据；DMA 写入 RAM 后，CPU 可能仍读到缓存中的旧数据。典型策略是：

```c
/* CPU -> DMA：写完缓冲区后清理 D-Cache */
SCB_CleanDCache_by_Addr((uint32_t *)tx_buf, tx_len);

/* DMA -> CPU：DMA 完成后使缓存失效，再读取缓冲区 */
SCB_InvalidateDCache_by_Addr((uint32_t *)rx_buf, rx_len);
```

地址和长度通常需要按 Cache line 对齐；不要只在“偶尔出错”时才添加缓存维护。另一种方案是把 DMA 区域配置为 non-cacheable，并在 MPU 中明确其属性。

## MPU 与内存布局

可以将代码区设为只读可执行、普通数据区设为可读写、外设区设为 device memory、DMA 缓冲区设为 non-cacheable。区域重叠时要确认优先级和对齐限制，启动阶段应先初始化 MPU，再启用缓存。

## CAN-FD 与高速通信

CAN-FD 同时涉及仲裁段、数据段、采样点、收发器能力和总线终端。调试时分开确认：控制器初始化、位时序、发送完成、中断、FIFO、过滤器以及错误状态。Ethernet、USB 和 SDMMC 等高速外设同样应先验证 DMA 描述符和内存可达性，再验证上层协议。

## 中断与实时性

600 MHz 不会自动消除实时性问题。要测量中断延迟、Cache miss、总线争用和高优先级任务占用。长耗时计算可放到任务或低优先级上下文，硬实时路径尽量使用定长缓冲和硬件触发。

## 选型提醒

GD32H759 的 Flash、RAM、引脚和外设实例随具体订货型号变化。工程开始时应固定：完整料号、封装、启动文件、链接脚本、CMSIS 设备包和数据手册版本。
