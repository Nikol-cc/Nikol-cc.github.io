# μC/OS 任务栈

## 为什么不能只看“任务还在运行”

任务没有立刻崩溃，不代表栈空间足够。日志、协议解析、局部数组和嵌套调用都可能让峰值栈使用量远高于平时。

## 高水位检查

创建任务前用固定字节填充栈空间，运行覆盖启动、通信突发、错误处理和日志输出等场景，再统计剩余填充值。记录任务名、优先级、栈总量和历史最低余量。

```text
task=uart_rx  priority=5  stack=2048  unused_min=612
task=protocol priority=7  stack=3072  unused_min=884
```

如果使用 μC/OS 自带统计接口，应确认接口版本和返回值单位；没有统计接口时再使用栈填充法。

## 和 DMA 中断配合

- 中断只完成硬件状态读取、缓冲区切换和消息投递。
- 协议解析、错误恢复和日志格式化放到任务中。
- 队列满、消息丢弃和处理超时都要有计数器。
- 检查高优先级任务是否长期占用 CPU，低优先级任务是否无法获得运行机会。
